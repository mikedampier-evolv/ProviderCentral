## Context

Snowflake's built-in email uses `SYSTEM$SEND_EMAIL(integration, recipients, subject, body)`. We already have a Flask proxy that calls Snowflake's SQL REST API with PAT auth. We can call the stored procedure through the same `/api/sql` endpoint.

The flow: user asks a question in chat → gets a response → types "email this to mike@example.com" → frontend detects the email intent, extracts the address, sends the last assistant response via `CALL SYSTEM$SEND_EMAIL(...)` through the proxy.

**Prerequisite**: A notification integration must exist. We'll create one (`H360_EMAIL_INT`) and the user's email must be verified in the account (Snowflake limitation).

## Implementation Steps

### 1. Create the email notification integration in Snowflake

Run SQL to create `H360_EMAIL_INT` (one-time setup):
```sql
CREATE NOTIFICATION INTEGRATION IF NOT EXISTS H360_EMAIL_INT
  TYPE = EMAIL
  ENABLED = TRUE;
```

### 2. Add `/api/email` endpoint to Flask (`server/app.py`)

New route that accepts `{ to: string, subject: string, body: string }` and calls:
```sql
CALL SYSTEM$SEND_EMAIL('H360_EMAIL_INT', :to, :subject, :body)
```
Uses the same PAT auth as `/api/sql`.

### 3. Update `useChatAgent.ts` to detect email commands

After receiving a response, if the user types something like "email this to mike@example.com" or "send to mike@example.com":
- Extract the email address via regex
- Take the last assistant message content
- Call `/api/email` with the address, a subject line ("Provider 360 Chat Results"), and the message body
- Show a confirmation message in the chat

### 4. Add an "Email" button to assistant messages in `ChatWidget.tsx`

Each assistant message gets a small mail icon button. Clicking it opens a mini prompt asking for the email address, then sends.

## Verification

- Type a question, get a response, click the email icon → enter address → confirm sent
- Or type "email this to user@example.com" → auto-sends
- Check Flask logs for successful SYSTEM$SEND_EMAIL call
