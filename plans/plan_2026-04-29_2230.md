# Week 3 Plan: Use-Case Marts (4 of 8)

## Context

**Current state:** 22 tables populated in HOSPITAL360_CUR (10 dims, 12 facts, ~5M rows). Governance applied. Week 2 complete.

**Explored data distributions:**
- Encounters: 200K (35% ED, 45% IP, 10% OP, 10% OBS)
- Denial rate: 10% across 4 reason categories (Eligibility, Medical Necessity, Coding Error, Auth Required)
- Readmission rate: ~12% across all encounter types
- Leakage rate: 15.3% across 8 specialties, evenly distributed
- OR: 30K cases across 6 blocks, ~70% first-case-on-time, avg 179 min case time + 29 min turnover
- DRG LOS variance available but uniform (seeded data uses flat random for LOS rather than DRG-driven)

**Target schemas:** Marts will be created as **tables** (not views) in their respective CUR domain schemas, following the existing pattern. Each mart pre-aggregates and enriches the conformed facts for its specific use case.

## Implementation Steps (2 SQL files)

### File 1: `infrastructure/11_mart_ddls.sql` — DDL for 4 mart tables

**UC1 — Patient Leakage Mart** (`HOSPITAL360_CUR.CLINICAL.MART_PATIENT_LEAKAGE`)
- Grain: 1 row per referral
- Joins: FCT_REFERRAL + DIM_PATIENT + DIM_PROVIDER (referring) + DIM_FACILITY
- Key columns: REFERRAL_ID, MRN, PATIENT_NAME, REFERRING_PROVIDER, REFERRED_TO_SPECIALTY, REFERRED_TO_NPI, REFERRAL_DATE, REFERRAL_MONTH, STATUS, LEAKAGE_FLAG, EXPECTED_REVENUE, LOST_REVENUE (=EXPECTED_REVENUE when leaked), FACILITY_NAME, PATIENT_ZIP, PATIENT_PAYER_TYPE, DAYS_SINCE_REFERRAL, IS_HIGH_VALUE (revenue > $5K)

**UC2 — Readmission & LOS Mart** (`HOSPITAL360_CUR.CLINICAL.MART_READMISSION_LOS`)
- Grain: 1 row per inpatient/observation encounter
- Joins: FCT_ENCOUNTER + DIM_PATIENT + DIM_PROVIDER + DIM_DRG + DIM_PAYER + DIM_DEPARTMENT + DIM_FACILITY
- Key columns: ENCOUNTER_ID, MRN, ADMIT_DATE, DISCHARGE_DATE, LOS_DAYS, EXPECTED_LOS (from DRG GEOMETRIC_LOS), LOS_VARIANCE (actual - expected), LOS_INDEX (actual/expected), IS_LONG_STAY (LOS_INDEX > 1.5), DRG_CODE, DRG_DESCRIPTION, DRG_WEIGHT, READMIT_30_FLAG, PAYER_TYPE, FACILITY_NAME, DEPT_NAME, DISCHARGE_DISPOSITION, TOTAL_CHARGES, TOTAL_COST, COST_PER_DAY, ADMIT_MONTH

**UC3 — OR Capacity Mart** (`HOSPITAL360_CUR.OPERATIONS.MART_OR_CAPACITY`)
- Grain: 1 row per OR case
- Joins: FCT_OR_CASE + DIM_PROVIDER (surgeon) + DIM_FACILITY + DIM_PROCEDURE_CPT
- Key columns: CASE_ID, OR_ROOM_ID, FACILITY_NAME, SURGEON_NAME, SPECIALTY, BLOCK_NAME, CASE_DATE, CASE_MONTH, SCHEDULED_START, ACTUAL_START, ACTUAL_END, DELAY_MINUTES (actual_start - scheduled_start), CASE_MINUTES, TURNOVER_MINUTES, BLOCK_MINUTES, UTILIZATION_PCT (case_min / block_min), FIRST_CASE_ON_TIME, PRIME_TIME_FLAG, CASE_CLASS, CPT_CODE, CPT_DESCRIPTION, IS_UNDERUTILIZED (util < 0.60)

**UC4 — Denials & RevCycle Mart** (`HOSPITAL360_CUR.FINANCIAL.MART_DENIALS_REVCYCLE`)
- Grain: 1 row per denied claim line
- Joins: FCT_CLAIM_LINE (denied only) + LEFT JOIN FCT_REMITTANCE + DIM_PAYER + DIM_PATIENT + DIM_PROVIDER + DIM_PROCEDURE_CPT + DIM_DIAGNOSIS_ICD10
- Key columns: CLAIM_ID, LINE_NUMBER, ENCOUNTER_ID, MRN, PAYER_NAME, PAYER_TYPE, SERVICE_DATE, SERVICE_MONTH, CHARGE_AMT, ALLOWED_AMT, DENIAL_REASON, CLAIM_STATUS, IS_APPEALED, APPEAL_WON (status='ADJUDICATED' after appeal), CPT_CODE, CPT_DESCRIPTION, ICD10_CODE, DX_DESCRIPTION, PROVIDER_NAME, FILING_DATE, DAYS_TO_FILE, IS_TIMELY_FILED (days_to_file <= payer.TIMELY_FILING_DAYS), DENIAL_CATEGORY (Eligibility/Auth/Coding/Medical Necessity), ESTIMATED_RECOVERY (charge_amt * appeal success rate by category)

### File 2: `infrastructure/12_seed_marts.sql` — Populate all 4 marts with INSERT...SELECT
