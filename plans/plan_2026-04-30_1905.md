# Week 6 Plan: Semantic Views + Cortex Analyst

## Context

**What I explored:**
- `CREATE SEMANTIC VIEW` DDL syntax from Snowflake docs — supports `TABLES`, `RELATIONSHIPS`, `FACTS`, `DIMENSIONS`, `METRICS`, `AI_SQL_GENERATION`, `AI_VERIFIED_QUERIES`
- 104 existing semantic views in this account for pattern reference
- Studied `AGENTOPS.AGENTOPS.AGENTOPS_SEMANTIC` as a well-structured multi-table example with verified queries, filters, metrics, and custom instructions
- All 4 mart column structures (35 + 22 + 29 + 30 columns), data distributions, and distinct value counts
- Cross-table join keys: ENCOUNTER_ID links readmission (106K) ↔ denials (90K, 63K overlap) ↔ OR capacity (30K); FACILITY_NAME is common across 3 of 4 marts
- ML prediction tables: forecast (360 rows), anomalies (736 rows), readmission drivers (92 rows), leakage drivers (98 rows)
- HOSPITAL360_APP has 2 empty schemas ready: `SEMANTIC_VIEWS` and `CORTEX_ANALYST`
- All 4 H360 roles already have USAGE on both schemas

**Key design decision — 1 unified semantic view vs 4 separate:**
- **Chosen: 1 unified semantic view** (`HOSPITAL360_ANALYTICS`) spanning all 4 marts + 2 ML tables with RELATIONSHIPS defined via ENCOUNTER_ID and FACILITY_NAME
- Rationale: Cortex Analyst works best with a single semantic view that captures the full domain model — users can ask cross-domain questions like "show me readmission rates for patients who also had denied claims" or "compare leakage rate vs OR utilization by facility"
- The 4 marts are denormalized already (they contain facility, payer, and specialty dimensions inline), so no separate dimension tables needed
- ML prediction tables included as separate logical tables (no joins needed — they're standalone reference data)

## Implementation Steps

### Step 1: Create `infrastructure/17_semantic_views.sql` — Single unified semantic view DDL

**CREATE SEMANTIC VIEW** `HOSPITAL360_APP.SEMANTIC_VIEWS.HOSPITAL360_ANALYTICS` with:

**6 Logical Tables:**
1. `readmissions` AS `HOSPITAL360_CUR.CLINICAL.MART_READMISSION_LOS` — PRIMARY KEY (ENCOUNTER_ID)
2. `leakage` AS `HOSPITAL360_CUR.CLINICAL.MART_PATIENT_LEAKAGE` — PRIMARY KEY (REFERRAL_ID)
3. `or_cases` AS `HOSPITAL360_CUR.OPERATIONS.MART_OR_CAPACITY` — PRIMARY KEY (CASE_ID)
4. `denials` AS `HOSPITAL360_CUR.FINANCIAL.MART_DENIALS_REVCYCLE` — PRIMARY KEY (CLAIM_LINE_SK)
5. `encounter_forecast` AS `HOSPITAL360_ML.PREDICTIONS.PRED_ENCOUNTER_VOLUME`
6. `denial_anomalies` AS `HOSPITAL360_ML.PREDICTIONS.PRED_DENIAL_ANOMALIES`

**3 Relationships:**
1. `readmissions(ENCOUNTER_ID) REFERENCES denials(ENCOUNTER_ID)` — readmit ↔ denied claims
2. `or_cases(ENCOUNTER_ID) REFERENCES readmissions(ENCOUNTER_ID)` — OR cases ↔ readmissions
3. `denial_anomalies(DENIAL_CATEGORY) REFERENCES denials(DENIAL_CATEGORY)` — anomaly context

**Facts (numeric columns, ~25):**
- readmissions: LOS_DAYS, EXPECTED_LOS, LOS_VARIANCE, LOS_INDEX, DRG_WEIGHT, TOTAL_CHARGES, TOTAL_COST, TOTAL_PAYMENTS, COST_PER_DAY, NET_REVENUE, PATIENT_AGE, HCC_SCORE
- leakage: EXPECTED_REVENUE, LOST_REVENUE, DAYS_SINCE_REFERRAL
- or_cases: DELAY_MINUTES, CASE_MINUTES, TURNOVER_MINUTES, BLOCK_MINUTES, UTILIZATION_PCT
- denials: CHARGE_AMT, ALLOWED_AMT, DAYS_TO_FILE, ESTIMATED_RECOVERY
- encounter_forecast: FORECAST_COUNT, LOWER_BOUND, UPPER_BOUND
- denial_anomalies: ACTUAL_COUNT, EXPECTED_COUNT, ACTUAL_CHARGES

**Dimensions (categorical + date columns, ~40):**
- readmissions: ENCOUNTER_TYPE, PAYER_TYPE, PAYER_NAME, FACILITY_NAME, DEPT_NAME, SPECIALTY, ATTENDING_PROVIDER, DRG_CODE, DRG_DESCRIPTION, MDC_DESCRIPTION, DISCHARGE_DISPOSITION, PATIENT_GENDER, IS_LONG_STAY, READMIT_30_FLAG, ADMIT_DATE, ADMIT_MONTH
- leakage: REFERRING_SPECIALTY, REFERRED_TO_SPECIALTY, REFERRING_PROVIDER, FACILITY_NAME, PATIENT_PAYER_TYPE, STATUS, LEAKAGE_FLAG, IS_HIGH_VALUE, REFERRAL_DATE, REFERRAL_MONTH, REFERRAL_QUARTER
- or_cases: FACILITY_NAME, SURGEON_NAME, SPECIALTY, BLOCK_NAME, CASE_DAY_OF_WEEK, CASE_CLASS, ASA_CLASS, FIRST_CASE_ON_TIME, IS_UNDERUTILIZED, IS_OVERTIME, PRIME_TIME_FLAG, CASE_DATE, CASE_MONTH
- denials: PAYER_NAME, PAYER_TYPE, DENIAL_CATEGORY, DENIAL_REASON, CLAIM_STATUS, IS_APPEALED, APPEAL_OUTCOME, CPT_CATEGORY, IS_TIMELY_FILED, SERVICE_DATE, SERVICE_MONTH

**Metrics (~18 computed aggregations):**
- readmissions: `readmission_rate` = AVG(CASE WHEN READMIT_30_FLAG THEN 1 ELSE 0 END) * 100, `avg_los_index` = AVG(LOS_INDEX), `long_stay_pct` = AVG(CASE WHEN IS_LONG_STAY THEN 1 ELSE 0 END) * 100, `encounter_count` = COUNT(ENCOUNTER_ID), `avg_cost_per_day` = AVG(COST_PER_DAY), `total_net_revenue` = SUM(NET_REVENUE)
- leakage: `leakage_rate` = AVG(CASE WHEN LEAKAGE_FLAG THEN 1 ELSE 0 END) * 100, `total_lost_revenue` = SUM(LOST_REVENUE), `referral_count` = COUNT(REFERRAL_ID), `high_value_leak_count` = SUM(CASE WHEN LEAKAGE_FLAG AND IS_HIGH_VALUE THEN 1 ELSE 0 END)
- or_cases: `avg_utilization` = AVG(UTILIZATION_PCT) * 100, `first_case_on_time_pct` = AVG(CASE WHEN FIRST_CASE_ON_TIME THEN 1 ELSE 0 END) * 100, `avg_delay_minutes` = AVG(DELAY_MINUTES), `case_count` = COUNT(CASE_ID)
- denials: `total_denied_charges` = SUM(CHARGE_AMT), `appeal_rate` = AVG(CASE WHEN IS_APPEALED THEN 1 ELSE 0 END) * 100, `timely_filing_pct` = AVG(CASE WHEN IS_TIMELY_FILED THEN 1 ELSE 0 END) * 100, `denied_claim_count` = COUNT(CLAIM_LINE_SK)

**AI_SQL_GENERATION instructions:**
Custom instructions explaining the 4 use cases, data date range (Jul 2023 – Dec 2024), table relationships, and guidance on how to answer common healthcare analytics questions.

**AI_VERIFIED_QUERIES (~12 verified queries):**
1. "What is the readmission rate by facility?" — pre-verified SQL
2. "What is the monthly readmission rate trend?" — trend query
3. "Which DRGs have the highest readmission rate?" — top-N
4. "What is the leakage rate by specialty?" — leakage analysis
5. "How much revenue was lost to patient leakage?" — financial impact
6. "What is the OR utilization by block?" — OR analysis
7. "Which blocks are underutilized?" — operational efficiency
8. "What are the top denial categories by charges?" — denial analysis
9. "What is the appeal success rate by category?" — appeal outcomes
10. "Show me the encounter volume forecast" — ML forecast
11. "Which denial categories have anomalies?" — ML anomaly detection
12. "What are the top readmission drivers?" — ML drivers (this one returns data from the PRED tables directly)
