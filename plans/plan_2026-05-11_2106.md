## Context

Currently, the alert form requires users to type raw SQL for the condition (e.g., `SELECT 1 FROM MART_READMISSION_LOS WHERE READMISSION_RATE > 0.15`). This is not demo-friendly for healthcare executives.

I explored the 6 mart tables and identified natural metric/threshold combinations that make sense as preset alerts. The approach: replace the raw SQL input with a **metric picker dropdown** and a **threshold input**. The backend will map the selected metric to the correct SQL condition.

## Design: Preset Metric Picker

The form will have:
1. **Metric dropdown** — friendly names like "Readmission Rate", "OR Utilization", "Overtime %", "Denial Rate", "Operating Margin", "Agency Staff %"
2. **Operator** — "exceeds" / "falls below" (auto-selected based on metric)  
3. **Threshold value** — numeric input (e.g., 15 for 15%)
4. **Email** — kept as-is
5. **Frequency** — kept as-is (dropdown)

The alert name will be auto-generated from the metric (e.g., `HIGH_READMISSION_RATE`).

The Flask backend `/api/alert` will accept either raw SQL (`condition` field) OR a new `metric` + `threshold` + `operator` combo, and map it to the correct SQL.

## Metric Presets (hardcoded in both frontend and backend)

| Metric Key | Display Name | SQL Condition Template | Default Operator |
|---|---|---|---|
| readmission_rate | Readmission Rate (%) | `SELECT 1 FROM HOSPITAL360_CUR.CLINICAL.MART_READMISSION_LOS HAVING AVG(READMIT_30_FLAG::INT) * 100 > :threshold` | exceeds |
| avg_los | Avg Length of Stay (days) | `SELECT 1 FROM HOSPITAL360_CUR.CLINICAL.MART_READMISSION_LOS HAVING AVG(LOS_DAYS) > :threshold` | exceeds |
| or_utilization | OR Utilization (%) | `SELECT 1 FROM HOSPITAL360_CUR.OPERATIONS.MART_OR_CAPACITY HAVING AVG(UTILIZATION_PCT) < :threshold` | falls below |
| overtime_pct | Overtime (%) | `SELECT 1 FROM HOSPITAL360_CUR.WORKFORCE.MART_STAFFING_QUALITY HAVING AVG(OT_PCT) > :threshold` | exceeds |
| denial_rate | Denial Rate (%) | `SELECT 1 FROM HOSPITAL360_CUR.FINANCIAL.MART_DENIALS_REVCYCLE HAVING SUM(CASE WHEN CLAIM_STATUS='DENIED' THEN 1 ELSE 0 END)*100.0/COUNT(*) > :threshold` | exceeds |
| operating_margin | Operating Margin (%) | `SELECT 1 FROM HOSPITAL360_CUR.FINANCIAL.MART_FINANCIAL_PERFORMANCE HAVING AVG(OPERATING_MARGIN)*100 < :threshold` | falls below |

## Implementation Steps

### 1. Update `ChatWidget.tsx` — Replace alert form

- Define a `METRIC_PRESETS` array with `{ key, label, defaultOp, defaultThreshold }`
- Replace the raw condition `<input>` with a `<select>` of metric presets
- Add a threshold `<input type="number">` with a label showing the operator ("exceeds" / "falls below")
- Auto-generate the alert name from the metric key (e.g., `HIGH_READMISSION_RATE`)
- Update the `alertTarget` state shape: replace `condition` with `metric` + `threshold` + `operator`

### 2. Update `useChatAgent.ts` — Update `createAlert` signature

- Accept `metric`, `threshold`, `operator` instead of raw `condition`
- POST to `/api/alert` with `{ name, metric, threshold, operator, email, schedule }`

### 3. Update Flask `server/app.py` — Map metric to SQL

- Define a `METRIC_PRESETS` dict mapping metric keys to SQL templates
- Replace `:threshold` placeholder with the user's value
- Keep backward compatibility: if `condition` is provided directly, use it (fallback for advanced users)
