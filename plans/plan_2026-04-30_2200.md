### Deliverables

#### Step 1: `infrastructure/21_tasks_automation.sql` — Snowflake Task DAG for automated refresh

Create a task DAG that automates the data pipeline:
- **Root task** `HOSPITAL360_ML.MONITORING.TASK_REFRESH_PIPELINE` — runs on daily schedule (CRON `0 6 * * *` UTC)
- **Task 1**: `TASK_REFRESH_MARTS` — re-populates the 4 use-case marts from fact/dim tables (MERGE or TRUNCATE+INSERT). Runs on `H360_XFM_WH`
- **Task 2**: `TASK_RETRAIN_FORECAST` — re-trains the encounter forecast model and regenerates predictions (AFTER marts complete). Runs on `H360_ML_WH`
- **Task 3**: `TASK_RETRAIN_ANOMALY` — re-trains the anomaly detection model and regenerates predictions (AFTER marts complete). Runs on `H360_ML_WH`
- **Task 4**: `TASK_LOG_PIPELINE_RUN` — logs pipeline execution metadata (timestamps, row counts, durations) into a new `HOSPITAL360_ML.MONITORING.PIPELINE_RUN_LOG` table (AFTER all 3 upstream tasks complete)
- All tasks use `WHEN SYSTEM$STREAM_HAS_DATA()` or run unconditionally (demo pattern — since data is static, unconditional is fine)
- Tasks are created in **suspended** state (demo-safe — user manually resumes or triggers `EXECUTE TASK` to demo)

#### Step 2: `infrastructure/22_monitoring_tables.sql` — Monitoring & observability tables

Create tables in `HOSPITAL360_ML.MONITORING`:
- **PIPELINE_RUN_LOG** — columns: RUN_ID, RUN_TS, TASK_NAME, STATUS (SUCCESS/FAILURE), ROWS_AFFECTED, DURATION_SECONDS, ERROR_MESSAGE
- **MODEL_PERFORMANCE_LOG** — columns: LOG_ID, LOG_TS, MODEL_NAME, METRIC_NAME, METRIC_VALUE (e.g., forecast MAPE, anomaly count) — populated by Task 4
- **DATA_QUALITY_CHECKS** — columns: CHECK_ID, CHECK_TS, TABLE_NAME, CHECK_NAME, CHECK_SQL, RESULT (PASS/FAIL), ROW_COUNT, DETAILS — stores DQ check results

#### Step 3: `infrastructure/23_data_quality.sql` — Data quality stored procedure

Create a stored procedure `HOSPITAL360_ML.MONITORING.SP_RUN_DATA_QUALITY_CHECKS()` that:
- Checks row count minimums on the 4 marts (e.g., mart_readmission_los > 100K)
- Checks for NULL primary keys on each mart
- Checks key metric reasonableness (e.g., readmission rate between 5-25%, leakage rate between 5-30%)
- Checks date range freshness (most recent data within expected bounds)
- Logs all results to `DATA_QUALITY_CHECKS` table
- Returns a summary

#### Step 4: `streamlit/pages/8_ops_monitor.py` — Operations & Monitoring page

New Streamlit page showing:

- **Model Performance**: Forecast accuracy metrics, anomaly detection summary from `MODEL_PERFORMANCE_LOG`
- **Platform Inventory**: Object counts across all 5 databases (tables, views, ML models, semantic views, agents, tasks) — a quick "platform health" view
