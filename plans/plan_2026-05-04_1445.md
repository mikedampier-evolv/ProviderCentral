## Context

The current `7_Cortex_Agent.py` uses `"stream": False` in the request and `resp.json()` to parse the response as a single JSON blob. However, the Cortex Agent `:run` API is an SSE (Server-Sent Events) streaming endpoint — it always streams. The current approach works but waits for the entire response before displaying anything, so the user sees only a spinner with no real-time thinking/text.

The official Snowflake quickstart ([sfguide-getting-started-with-cortex-agents](https://github.com/Snowflake-Labs/sfguide-getting-started-with-cortex-agents)) uses `sseclient-py` to parse SSE events and progressively renders text, thinking, tables, tool use/results, charts, and status messages in real-time.

**Key SSE event types from the Cortex Agent API:**
- `response.status` → spinner/status text (`{"status": "...", "message": "..."}`)
- `response.thinking.delta` → incremental thinking tokens (`{"content_index": N, "text": "..."}`)
- `response.thinking` → complete thinking block
- `response.text.delta` → incremental text tokens (`{"content_index": N, "text": "..."}`)
- `response.tool_use` → tool invocation details
- `response.tool_result` → tool results
- `response.table` → result set data with column metadata
- `response.chart` → Vega-Lite chart spec
- `error` → error events
- `response` → final complete message (to store in history)

## Implementation Steps

### Step 1: Add `sseclient-py` to `requirements.txt`
Add `sseclient-py` as a dependency (line 3).

### Step 2: Rewrite `call_agent()` in `7_Cortex_Agent.py`
- Remove `"stream": False` from the request body
- Add `stream=True` to `requests.post()` to enable chunked transfer
- Return the raw `requests.Response` instead of parsed JSON

### Step 3: Add `stream_events()` function
Following the official quickstart pattern:
- Use `sseclient.SSEClient(response).events()` to iterate SSE events
- Use `defaultdict(str)` for text buffers keyed by `content_index`
- Use `defaultdict(content.empty)` for Streamlit placeholder containers keyed by `content_index`
- Handle each event type with a `match event.event` block:
  - `response.status` → update spinner text
  - `response.thinking.delta` → append to thinking buffer, render in an expanded expander
  - `response.thinking` → collapse the expander with final text
  - `response.text.delta` → append to text buffer, render with `st.markdown()`
  - `response.tool_use` → show in expander
  - `response.tool_result` → show in expander
  - `response.table` → parse result_set data into pandas DataFrame, display with `st.dataframe()`, add auto-chart
  - `response.chart` → render with `st.vega_lite_chart()` if present
  - `error` → display error, pop last user message
  - `response` → store final complete message in session state

### Step 4: Update `process_agent_question()`

  - Call the streaming `call_agent()` to get the response object
